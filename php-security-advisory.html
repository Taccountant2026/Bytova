VERIFIED SECURITY BULLETIN

Critical PHP vulnerabilities:
what to do now.

Identify PHP across your infrastructure, confirm the relevant vendor fix and plan an authorised update.

Published 22 October 2026 · Sources checked 22 October 2026 · Next review due 29 October 2026

What the researchers found

The PHP project published two critical memory-safety advisories on 21 October 2026, each rated 9.2 under CVSS 4.0. One concerns interrupted out-of-memory handling and unfinished request data. The other concerns references to request memory that outlive the memory itself and can be used by a later request.

The advisories credit the original reporters and PHP remediation developers. Bytova provides educational tools and guidance; it makes no discovery claim.

Sources: PHP: RCE via OOM corruption · PHP: RCE via stale global state.

What remote code execution means

Remote code execution (RCE) means an attacker may cause a server to execute attacker-controlled instructions. The demonstrated PHP impact runs with the web worker account’s permissions. Depending on that account’s access, consequences can include altered pages, exposed application data, stolen application secrets or interrupted services. It does not automatically mean administrator or root access.

PHP reports a complete unauthenticated exploit against Apache mod_php. Other web PHP handlers also require assessment; differences in demonstrated exploit reliability are not a reason to leave an affected runtime unpatched.

Sources: PHP: RCE via OOM corruption · PHP official security announcement.

Who needs to act

Administrators of PHP-backed websites, APIs, WordPress and other PHP applications should identify their actual runtime and package source. Check hosting services and appliances that bundle PHP as well as servers you manage directly. A static HTML website does not itself run PHP; linked services and other infrastructure still need their own assessment.

Updating WordPress, a theme or a plugin alone does not replace a PHP runtime update. Ask your host who manages PHP, which package revision includes both fixes and when the running workers were replaced.

Sources: UK NCSC: Critical security issue affecting PHP · Cloudflare: observed attack traffic and WAF protections.

Research demonstrations and observed attacks

PHP’s advisories describe demonstrated exploitation under specific conditions. Separately, Cloudflare’s 21 October article reports attack traffic targeting its customers and attempts to vary payloads. That is evidence of observed attack attempts; it is not a verified count of successful compromises or proof about your website.

Keep any existing defensive controls in place while applying the official fix. A firewall rule, changed upload setting or quiet log does not establish that an affected PHP runtime is safe.

Sources: Cloudflare: observed attack traffic and WAF protections · PHP: RCE via OOM corruption.

Get the official update

Use the dedicated official patch and update centre to choose the right route for Windows, Linux, source builds or managed hosting. Downloads stay with PHP and your vendor.

A safe response

  1. Inventory affected services and identify their authorised administrator.
  2. Check the actual package against both official advisories.
  3. Preserve evidence and involve a qualified responder if compromise is suspected.
  4. Verify backups, test the intended update and apply vendor-approved packages.
  5. Replace affected running workers, validate service and document the result.

PHP states that updating to a release containing the fixes is the complete remedy. Temporary measures have limitations. Follow the current official advice with your administrator rather than copying generic memory-limit changes.

Sources: PHP official security announcement · UK NCSC: Critical security issue affecting PHP.
