### 2 — Backports matter

An older PHP version number does not always tell the whole patch story.

Linux distributions and other vendors can apply a fix to an older release and issue a new package revision. That means a useful security check needs the vendor, operating-system release, package family and complete revision — plus confirmation that the website uses that installed package.

Bytova’s free PHP checker recognises a small set of verified exact package fixes. Unknown packages return an unverified result and a route to the official records.

Read the explanation and check carefully: https://bytova.co.uk/php-version-checker.html

Sources checked 22 October 2026. A version result is not a compromise assessment.

### 3 — Safe update plan

A useful patch record answers more than “did we install an update?”

Which runtime served the website? Was the recovery copy tested? Which vendor package addressed both advisories? Were running workers replaced? Did the important customer journeys still work?

Bytova’s free ten-step guide and printable checklists help administrators work through those questions in an authorised process.

If there are signs of compromise, involve your hosting provider and a qualified incident responder. Applying a PHP update alone does not establish that an existing intrusion has been removed.
